# 3. XML-first: the fiscal XML is the source of truth

- Status: accepted
- Date: 2026-11

## Context

NF-e and NFS-e are issued as signed XML; the PDF (DANFE, printed NFS-e) is a rendering of it. When the XML arrives with the PDF, every field it contains is known exactly, and reading it costs no model call. XML from outside is still untrusted input: entity expansion, external entities and oversized files are real attacks.

## Decision

- Parse XML only with `defusedxml`, after a size limit, and map it to the same schema as the LLM output (`extract/xml_reader.py`). An XML whose type does not match the classified PDF, or whose access key fails its check digit, is ignored and the document gets a review reason.
- With `DOCAI_XML_FIRST=true` (default) and a complete XML, the LLM is not called. When the XML lacks fields (for example the NFS-e services table), the LLM fills only the gaps.
- When both exist, the XML wins field by field; every disagreement is a correction finding, so a model that misread the PDF is visible in the report.
- XML values that are not printed on the PDF are flagged: the printout may not belong to that XML.

## Consequences

- On the evaluation corpus, XML-first halves the LLM calls on documents with XML and removes their extraction errors (see the XML section of `reports/eval_report.md`).
- XML signatures are not verified yet (planned); a forged XML is trusted as much as the PDF it came with.
- CT-e XML is not generated by the synthetic corpus, so CT-e always goes through the LLM.
